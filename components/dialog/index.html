Components / Dialog

Dialog

A dialog on the native dialog element, in three placements: centered for a decision, over a scrim; at the end for a side panel beside the page, with no scrim; at the bottom for a sheet on phones. The browser handles focus.

  • Native HTML
  • 9.0 KB gzipped · script and styles
  • @orbex/sonar-components/dialog

Examples

Usage

  • Confirm only what cannot be undone, such as resetting a layout. Everything else gets an undo in a toast.
  • The title asks the question; the main action answers it with a verb, last in the row.
  • Panels open at the end on tablets and desktops, from 600 px wide (an iPad mini in portrait keeps them at the side), and from the bottom on phones, 44 px from the top of the window. On a tablet this departs from the product’s 768 px size class, on purpose: the side panel keeps the overview in view. On desktops a side panel slides in 48 px with a fade, as in the product; on tablets it slides all the way in from the right edge, as Navigation by device defines.
  • Nothing in a panel or sheet shows the system’s scrollbar: its body scrolls with the product’s thin indicator, 4 px from the edge.
  • A side panel is not modal (modal={false}): it starts under the top bar, has no scrim, and the overview stays in view with the row it came from marked. Only decisions, such as a confirmation, take a scrim.
  • The six panels the overview opens are gathered, live, in Patterns › Panels.
  • Turn dismissible off when a stray click outside would lose what someone typed.

Do and don’t

Accessibility

Keyboard

Key What it does
Tab and Shift Tab Move among the dialog’s controls only; the page behind is inert.
Escape Closes the dialog and returns focus to what opened it.

Roles and attributes

Element or attribute What it gives
<dialog> opened with showModal() The browser moves focus in, keeps it inside and makes the rest of the page inert.
aria-labelledby, aria-describedby The title names the dialog; the description is read after it.
Close button Named by closeLabel, “Close” by default.
Body that scrolls (side panels and sheets) A group named by the title while it scrolls, so the keyboard can scroll it; the indicator beside it is drawn and hidden.

Notes

  • Modal: showModal() moves focus into the dialog, keeps it there, makes the rest of the page inert and returns focus to the trigger on close.
  • Side panel: focus moves into the panel when it opens and back to the trigger when it closes. Tab and Shift+Tab go round inside it, so focus never lands on the page behind; the page stays in view and a click on it still works. On phones, where it is a sheet over the page, the rest of the page is inert while it is open. Escape or a click outside closes it.
  • The title names the dialog and the description is read with it.
  • Escape and the close button always close it, whatever dismissible says.
  • With reduced motion, the dialog fades without moving.

Use it

Each component is its own entry point with its own stylesheet, so an app loads only what it uses. The tokens and the cascade layers are set once for the app: see Installation.

tsx 
import { DialogHost, Dialog } from '@orbex/sonar-components/dialog'
import '@orbex/sonar-components/dialog.css'

DialogHost

Holds the side panels and sheets written inside it, as a drawn app frame does, instead of placing them against the window.
